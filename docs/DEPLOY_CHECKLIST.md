# Чек-лист деплоя

## 1. Перед релизом

- Убедиться, что локальная ветка `main` синхронизирована с GitHub.
- Проверить, что все нужные изменения закоммичены и запушены.
- Проверить, что нет незакоммиченных файлов в рабочем дереве.

## 2. Обязательные локальные проверки

```bash
go test ./...
go build ./cmd/server
cd webapp-react && npm run build
```

Если что-то не прошло, деплой не делать до выяснения причины.

## 3. Проверка инфраструктуры

- `BOT_TOKEN` задан и актуален.
- `GOOGLE_SHEETS_ID` указывает на рабочую таблицу.
- `GOOGLE_SHEETS_CREDENTIALS` или `GOOGLE_SHEETS_CREDENTIALS_BASE64` заданы корректно.
- `WEBAPP_URL` совпадает с реальным публичным адресом Mini App.
- `GROUP_ID` и `GROUP_LINK` заполнены, если используется сценарий группового чата.
- `DEBUG=false` для production.

## 4. Проверка данных Google Sheets

- Лист `Список гостей` существует и доступен сервисному аккаунту.
- Служебные листы (`Игры`, `Wordle*`, `Кроссворд_Прогресс`, `Фото`) доступны.
- Нет критичных ручных правок в заголовках листов.
- Если вносились изменения в схему, документация обновлена.

## 5. После деплоя

Проверить вручную:

- `GET /health` возвращает `200`.
- `GET /api/config` отвечает корректно.
- Mini App открывается без белого экрана.
- Бот отвечает на `/start`.
- Регистрация работает.
- Игры открываются и не падают на первом запросе.
- Тайминг и рассадка читаются.

## 6. Smoke-проверка логов

После запуска сервиса проверить:

- нет ошибок инициализации Google Sheets;
- нет ошибок запуска Telegram-бота;
- нет ошибок проверки структуры листов;
- планировщик `daily_reset` стартовал;
- HTTP сервер поднялся на ожидаемом порту.

## 7. При откате

- Вернуться к предыдущему стабильному commit/образу.
- Проверить, что frontend bundle и backend соответствуют одной ревизии.
- Повторно проверить `/health`, `/api/config` и `/start` у бота.
