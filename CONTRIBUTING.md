# Contributing

## Базовые правила

- Не менять пользовательское поведение без явной задачи.
- Не коммитить `.env.local`, локальные базы, бинарники и cache-артефакты.
- Любое изменение backend или frontend сопровождать локальной проверкой.
- Если меняется поведение запуска, конфиг или деплой, документацию нужно обновить в том же PR/commit.

## Локальная подготовка

```bash
cp .env.example .env.local
make deps
```

## Обязательные проверки перед commit

```bash
make verify
```

Если менялись чувствительные части backend, дополнительно:

```bash
go test -race ./cmd/... ./internal/...
```

## Стиль коммитов

Предпочитаемые префиксы:

- `fix:`
- `cleanup:`
- `docs:`
- `chore:`
- `test:`

Коммит должен быть атомарным и описывать один логический блок изменений.

## Работа с фронтендом

- Исходники живут в `webapp-react/`.
- Production bundle попадает в `webapp/`.
- После изменения frontend-кода нужно проверить и lint, и build.

## Работа с секретами

- Секреты только в `.env.local` или внешнем secret manager.
- Если секрет когда-либо попал в Git, его нужно считать скомпрометированным и ротировать.
